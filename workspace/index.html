Methodology
How this estimate was built
—

          
Method summary

          
    
            
  1. The problem: a turbine stops reporting during an outage, so there's no record of what wind it actually experienced.
    2. 
            
  2. The approach: nearby turbines kept reporting, and wind behaves similarly between turbines that have historically moved together.
    3. 
            
  3. Find the best stand-in: compare every other turbine's pre-outage history to the affected one's, and pick whichever single turbine tracked it most closely — not an average of several.
    4. 
            
  4. Translate its readings: adjust the stand-in's wind speed to match how the affected turbine typically runs relative to it, rather than copying its numbers directly.
    5. 
            
  5. Turn wind into electricity: run the translated wind speed through the turbine's own known performance curve.
    6. 
            
  6. Add it up: sum the resulting power over the outage window into a total missing-kWh figure.
    7. 
            
  7. Check trustworthiness separately: test the same method on a period where the real answer is already known — the resulting error becomes the basis for the interval shown with the estimate.
    8. 
            
  8. Monetary loss: convert the missing kWh to a currency figure, labeled illustrative unless the price is real and sourced.
    9. 
          


          

            
Reconstruction
—
vtarget(t) ≈ a + b · vreference(t), fit to match the target's own variance rather than minimize error — this avoids under-predicting energy.

            
Energy calculation
—
Lost energy = Σ P(vtarget(t)) · Δt, using the turbine's own power curve and a 10-minute reading interval.

          

          
Limitations
    
          
    Other methods considered
    
          
    
            
      
              
    • Direct power regression (reference turbine's power output → target's power output directly) — excluded because no BayWa source file contains a power column.
      • 
              
    • Naive averaging of other turbines (no wind reconstruction, no fitting) — competitive at same-farm distance, loses clearly once turbines are far apart.
      • 
              
    • Multi-turbine blend (averaging several reference turbines) — ties or slightly underperforms a single well-chosen reference at real cross-farm distance; kept as a documented alternative.
      • 
              
    • Multi-turbine machine-learning ensemble — more accurate on one target, comparable on the other two, but far more complex and slower: ~27 seconds to fit one target versus a few seconds for this method's full run (30-90x). Not shipped for that complexity and speed cost, not for lower accuracy.
      • 
            
    
            
    Wind-first single-reference reconstruction shipped for the combination of model precision and a calculation straightforward enough to explain to an insurer.
    
          
    

          
    Next steps
    
          
    
            
      
              
    • A reliable confidence range, once enough test data exists to calculate one properly.
      • 
              
    • Automatic outage-cause classification (sensor fault vs. mechanical outage).
      • 
              
    • A multi-turbine ensemble, if accuracy on harder targets outweighs the added complexity and run time.
      •
